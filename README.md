## ✨ ویژگی‌های کلیدی

> [!TIP]
> **📊 پنل مدیریت**
> - داشبورد و آمار زنده، لیست کانفیگ‌ها، اتصالات فعال و لاگ فعالیت
> - 🗂 گروه‌های ساب (Subscription Groups) برای ارسال یکجای چند کانفیگ
> - 🎚 محدودیت ترافیک، سرعت و تعداد IP برای هر کانفیگ
> - 👥 مدیریت ادمین‌ها با دسترسی‌های جداگانه

> [!TIP]
> **🌐 پروتکل‌ها**
> - 🔐 VLESS (Reality، gRPC Reality، XHTTP) و VLESS WebSocket
> - 🛡 VMess و Trojan
> - ⚡ Shadowsocks، Hysteria2، TUIC، AnyTLS، Naive، ShadowTLS، Snell
> - 🔌 SOCKS5 و HTTP

> [!TIP]
> **🧰 ابزارهای تکمیلی**
> - ☁️ اسکنر IP تمیز Cloudflare و 🔎 اسکنر SNI برای Reality
> - 🤖 ربات تلگرام برای مدیریت و فروش اشتراک
> - 🌩 ONEX Edge: رله Cloudflare Worker جلوی پنل
> - 📦 هسته SideRail (Xray) که در اولین اجرا خودکار دانلود می‌شه

## 🧩 حالت‌های پروتکل: ONEX VIP و Cloudflare

> [!NOTE]
> **💎 ONEX VIP (پروتکل‌های عمومی):** یک سرویس با چند پروتکل از پنل ساخته می‌شه و کاربر بین اون‌ها جابجا می‌شه.
> *مثال:* اشتراک VIP با VLESS Reality برای مسیرهای سریع و Trojan برای شبکه‌های سخت‌گیرانه.

> [!NOTE]
> **☁️ Cloudflare (VMess / VLESS / Trojan):** کانفیگ‌ها روی WebSocket ساخته می‌شن و از طریق ONEX Edge به Cloudflare وصل می‌شن.
> *مثال:* اشتراک Cloudflare با `vless-ws` و `trojan-ws` برای زمانی که IP مستقیم سرور فیلتره.

---

## 🔍 اسکنرها

> [!TIP]
> **☁️ اسکنر IP تمیز Cloudflare**
> آدرس‌های IP سالم Cloudflare رو پیدا می‌کنه. لیست‌ها شامل IPv4، IPv6، رنج‌های Cloudflare و دامنه‌های ECH از مخزن پروژه هستن. نتیجه مستقیم به لینک‌های Edge اعمال می‌شه.

> [!TIP]
> **🔎 اسکنر SNI برای Reality**
> مقصدهای مناسب Reality رو بررسی می‌کنه. لیست پیش‌فرض در `config/sni_reality.txt` هست و از طریق `POST /sni` هر هاستی رو می‌تونی تست کنی.
> *مثال:* اگه `www.example.com` پاسخ TLS سالم بده، می‌تونی اون رو به عنوان SNI در inbound Reality استفاده کنی.

## 🌩 ONEX Edge (Cloudflare Worker)

> [!IMPORTANT]
> با یک **API Token** از Cloudflare، پنل Worker رو خودکار روی اکانت تو آپلود و فعال می‌کنه (روی `workers.dev` یا دامنه اختصاصی روی یک Zone). بعدش به هر ساب، نسخه "☁️ Edge" از کانفیگ‌های WebSocket اضافه می‌شه.

> [!CAUTION]
> توکن Cloudflare فقط در `DATA_DIR/cf_edge.json` ذخیره می‌شه و هرگز نباید وارد Git بشه.

## 🤖 ربات تلگرام

> [!TIP]
> **👑 منوی ادمین:** 📊 داشبورد زنده · 🟢 لیست و ➕ ساخت کانفیگ · 🗂 گروه‌های ساب · 🔌 اتصالات زنده · 📜 لاگ · 🛒 فروشگاه · ⚙️ تنظیمات

> [!TIP]
> **👤 منوی کاربر:** 🛒 خرید اشتراک · 📦 کانفیگ‌های من · 📊 وضعیت مصرف · 🧾 سفارش‌های من · 🔗 دریافت لینک‌ها

> [!NOTE]
> **💳 فروش اشتراک:** کاربر پلن رو انتخاب می‌کنه، رسید کارت به کارت یا لینک پرداخت می‌فرسته و ادمین‌ها با ✅ تایید یا ❌ رد می‌کنن. بعد از تایید، لینک ساخته و برای خریدار ارسال می‌شه. ربات می‌تونه قبل از تحویل، عضویت در کانال اجباری (Force Join) رو هم چک کنه.

## 🚀 نصب و دیپلوی

| پلتفرم | فایل | توضیح |
|---|---|---|
| 🚂 Railway | `railway.toml` | ساده‌ترین راه برای شروع. فقط HTTP و WebSocket |
| 🎨 Render | `render.yaml` | با دیسک پایدار. فقط HTTP و WebSocket |
| 🐨 Koyeb | `koyeb.yaml` | سرویس Docker. فقط HTTP و WebSocket |
| 🪁 Fly.io | `fly.toml` | Volume روی `/data`. پشتیبانی از TCP و UDP |
| 🖥 VPS | `start.sh` | نصب با systemd و کاربر محدود |

> [!WARNING]
> **Reality، Hysteria2 و TUIC** به TCP یا UDP واقعی نیاز دارن و روی Railway، Render و Koyeb کار نمی‌کنن. برای این پروتکل‌ها Fly.io یا VPS رو انتخاب کنید. پروتکل‌های WebSocket (VLESS-WS، VMess-WS، Trojan-WS) روی همه این پلتفرم‌ها کار می‌کنن.

### 🚂 دیپلوی روی Railway (و پلتفرم‌های مشابه)

> [!IMPORTANT]
> 1. ریپوی پروژه رو با **مجوز کتبی** از صاحب پروژه Fork کنید.
> 2. ریپو رو به یک پروژه جدید روی Railway وصل کنید.
> 3. یک Volume به مسیر `/data` وصل کنید تا داده‌ها بعد از redeploy از بین نرن.
> 4. متغیرهای محیطی رو تنظیم کنید.
> 5. Deploy کنید و منتظر بمونید تا Build و Health check (`/health`) کامل بشه.
> 6. آدرس تولیدشده رو باز کنید و وارد پنل بشید.

روی Render، Koyeb و Fly.io هم روند مشابهه. فایل مربوط به هر پلتفرم رو از جدول بالا استفاده کنید.

### 🖥 دیپلوی روی VPS

```bash
sudo ONEX_REPO=https://github.com/OWNER/REPO.git ./start.sh
```

## ⚙️ متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `PORT` | پورت سرویس (پیش‌فرض ۸۰۰۰) |
| `DATA_DIR` | مسیر داده‌ها. روی محیط ابری حتماً به Volume وصل بشه |
| `ONEX_PUBLIC_URL` | آدرس عمومی، اگر پلتفرم خودکار اعلام نکنه |
| `SECRET_KEY` | کلید اختیاری. اگر خالی باشه، خودکار ساخته و در `DATA_DIR` ذخیره می‌شه |

> [!TIP]
> نمونه کامل در `.env.example` هست.
